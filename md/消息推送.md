## 一、整体架构概览

本项目的客户端消息推送基于 **Firebase Cloud Messaging (FCM)** 实现，整体分为三大子系统：

| 子系统 | 说明 | 核心入口 |
|--------|------|----------|
| **推送配置管理** | 后台管理推送规则的 CRUD | `PushMsgController` |
| **定时推送调度** | XXL-Job 定时扫描 + 触发推送 | `TimerHandler` → `TimerServiceImpl.push()` |
| **Firebase 推送执行** | 封装 FCM API，支持 Token 精准推送 & Topic 广播 | `FireBaseServiceImpl` |

另外还有两个辅助子系统：
- **设备 Token 管理**：客户端上报 FCM Token → `PushTokenController`
- **活动推送规则**：APP 端活动入口推送（AB实验驱动）→ `ActivityPushRuleController`

## 四、四种推送触发类型

由枚举 `PushMsgEnum` 定义：

| Code | 枚举 | 含义 | 触发时间字段 | 触发时间计算逻辑 | 关联字段 |
|------|------|------|-------------|-----------------|---------|
| `appoint` | TRIGGER_TYPE_APPOINT | 新剧预约 | `dramaOnlineTime` | 直接解析 `dramaOnlineTime` | playId, seriesId, dramaOnlineTime |
| `sign` | TRIGGER_TYPE_SIGN | 签到 | `signTime` | 若今天该时间已过则取明天，否则取今天 | signTime |
| `drama` | TRIGGER_TYPE_DRAMA_PUSH | 新剧推送 | `dramaPushTime` | 直接解析 `dramaPushTime` | playId, seriesId, dramaPushTime |
| `subscription` | TRIGGER_TYPE_SUBSCRIPTION_EXPIRE | 订阅到期 | 无固定时间 | 返回 null（由订阅到期事件驱动） | subscriptionExpire(小时数) |

### 触发时间计算 (`calculateTriggerTime`)

```java
// appoint → 解析 dramaOnlineTime (yyyy-MM-dd HH:mm:ss)
// sign    → 若当前时间已过今天signTime则取明天，否则取今天
// drama   → 解析 dramaPushTime (yyyy-MM-dd HH:mm:ss)
// subscription → return null (无固定触发时间)
```

### 定时任务实际筛选的类型

> ⚠️ 注意：虽然枚举定义了 4 种类型，但定时任务 `filterTriggerPushList` **只处理 2 种**：
> - `sign` — 签到（时分秒比较）
> - `drama` — 新剧推送（完整时间比较）
>
> `appoint`（新剧预约）和 `subscription`（订阅到期）**不参与定时推送筛选**

## 五、推送配置管理 (后台 CRUD)

### 5.1 PushMsgController API

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/push/page` | 分页查询推送配置 | 已注释 |
| GET | `/push/{id}` | 根据ID查询推送 | 已注释 |
| POST | `/push` | 新增推送配置 | 已注释 |
| PUT | `/push` | 修改推送配置 | 已注释 |
| PUT | `/push/states/{id}` | 修改推送状态(启用/禁用) | 已注释 |

> ⚠️ 所有 `@PreAuthorize` 权限注解均已注释，标注 `//todo 系统配置`

### 5.2 分页查询逻辑 (`queryPage`)

```
1. 按条件分页查询 sys_push 表
2. 补充语言名称: 批量查询 langId → langName
3. 补充订阅主题名称: 从字典表 SUBSCRIPTION_TOPIC 匹配 subscriptionTopicId → subscriptionTopicName
4. 补充推送用户: 查询 PushUser 关联表, 按 pushId 分组
   → 查 SysUserDAO 获取用户 userId 列表 (逗号分隔字符串)
```

### 5.3 新增推送逻辑 (`addSysPush`)

```
1. 校验 triggerTypeCode 不为空且为合法枚举值
2. 查询短剧名/剧集名回填 (playAdapter)
3. DTO → DAO 转换 (PushConvert.addToDao), triggerTypeCode → triggerType(中文名)
4. 计算触发时间 (calculateTriggerTime)
5. 语言回填: 若 langId 为空但 subscriptionTopicId 不为空, 从字典表取 topic 对应语言
6. 保存推送主记录 (pushRepository.save)
7. 解析 multiUserIds (逗号分隔字符串) → 查库校验 → 批量保存 PushUser 关联
```

### 5.4 修改推送逻辑 (`updateSysPush`)

```
1. 校验 ID 和记录存在性
2. 查询短剧名/剧集名回填
3. ★ 触发类型变更处理: 若修改了 triggerTypeCode, 将不相关字段置空:
   - appoint: 置空 signTime, dramaPushTime, subscriptionExpire
   - sign: 置空 dramaOnlineTime, dramaPushTime, subscriptionExpire, playId, playName, seriesId, seriesName
   - drama: 置空 dramaOnlineTime, signTime, subscriptionExpire
   - subscription: 置空 dramaOnlineTime, signTime, dramaPushTime, playId, playName, seriesId, seriesName
4. 转换 + 计算触发时间
5. ★ triggerTime 为空时返回失败 (与 addSysPush 逻辑不一致)
6. 更新主记录
7. 先删后增推送用户关联 (pushUserRepository.remove → saveBatch)
```

### 5.5 状态修改逻辑 (`editStates`)

```
1. 校验 ID 和 states 参数
2. 查询记录是否存在
3. 更新 states 字段 (true=开启, false=关闭)
```

## 六、设备 Token 管理 (客户端上报)

### 6.1 PushTokenController API

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | `/app/token` | 客户端上报 FCM Token | `hasAuthority('/app/token/add')` |
| POST | `/app/user/topics` | 获取用户可订阅的主题列表 | 已注释 |

### 6.2 Token 上报逻辑 (`PushTokenServiceImpl.getToken`)

```
1. 获取当前登录用户 userId
2. 加分布式锁 (Redisson, 5秒超时)
3. 按 deviceId 查询是否已有记录:
   - 有 → 更新 token 和 updateTime
   - 无 → 新增 user_device 记录 (userId, deviceId, token, deviceSys, timeCity)
4. 释放锁
```

### 6.3 订阅主题查询逻辑 (`getTopics`)

```
1. 获取当前用户 langId
2. 查询字典表 topic=SUBSCRIPTION_TOPIC 的所有字典项
3. 过滤出 dictValue == langId 的项 (即该语言对应的 FCM Topic)
4. 返回 SubscriptionTopicDictVO 列表
```

> 字典表 `SUBSCRIPTION_TOPIC` 中: `dictName` = FCM Topic 名称, `dictValue` = 语言ID

## 七、定时推送调度 (核心执行链路)

### 7.1 调度入口

通过 **XXL-Job** 调度，注册在 `TimerHandler`：

```java
@XxlJob("push")
@ApiOperation("定时任务推送")
public Result<?> push(String param) {
    timerService.push();
    return Result.success();
}
```

### 7.2 推送执行主流程 (`TimerServiceImpl.push`)

```
1. 获取当前时间 now, now+5min
2. 查询所有启用的推送规则 (pushRepository.getUsableList)
3. filterTriggerPushList() 筛选需要触发的规则:
   - sign 类型: signTime 在 [now, now+5min] 内 (只比较时分秒)
   - drama 类型: dramaPushTime 在 [now, now+5min] 内 (比较完整日期时间)
   - appoint/subscription: 不参与定时推送
4. 遍历每条规则:
   4.1 语言校验: 短剧语言必须与推送 topic 语言一致, 否则跳过
   4.2 判断是否绑定用户 (push_user表):
       - 有绑定用户 → pushByTokens (精准推送)
       - 无绑定用户 → pushByTopic (Topic广播)
```

### 7.3 Token 精准推送 (`pushByTokens`)

```
1. 获取推送规则绑定的用户ID列表 (push_user表)
2. 按语言筛选: 只保留 langId 与推送规则一致的用户 (userRepository.getUserIdsByIdsAndLangId)
3. 查询这些用户的设备Token (user_device表)
4. 构建 PushMsgDTO (title, msg, type, playId, seriesId, indexType, tokens)
5. 调用 fireBaseService.push(pushMsgDTO) 执行推送
6. 返回推送结果 (successCount, failCount)
```

### 7.4 Topic 广播推送 (`pushByTopic`)

```
1. 构建 PushMsgDTO (title, msg, type, playId, seriesId, indexType)
2. 从字典表获取 subscriptionTopicId 对应的 topic 名称
3. 设置 pushMsgDTO.subscriptionTopic = topic名称
4. 调用 fireBaseService.push(pushMsgDTO) 执行推送
5. 返回推送结果 (topicResult: true/false)
```

### 7.5 时间筛选逻辑 (`filterTriggerPushList`)

```java
sign 类型:
  // 将 signTime 的时分秒与当前日期组合
  // 判断组合后的时间是否在 [now, now+5min) 内
  // 注意: 不处理跨天场景 (如 23:58 ~ 00:03 会漏触发)

drama 类型:
  // 直接判断 dramaPushTime 是否在 [now, now+5min) 内

appoint / subscription:
  // 不参与定时推送, 返回 false
```

### 7.6 签到时间比较 (`isSignTimeInRange`)

```java
// 将 signTime 的年月日设为当前日期
signCal.set(nowCal.get(Calendar.YEAR), nowCal.get(Calendar.MONTH), nowCal.get(Calendar.DAY_OF_MONTH));
Date signDateToday = signCal.getTime();

// 检查签到时间是否在 [now, nowAdvance5Min) 内
return (signDateToday.equals(now) || (signDateToday.after(now) && signDateToday.before(nowAdvance5Min)));
```

> ⚠️ 此实现**不处理跨天场景**：如果当前时间是 23:58，advance 是 00:03，签到时间 00:01 会被漏掉

## 八、Firebase 推送执行层

### 8.1 初始化

```java
@PostConstruct
public void init() {
    // 读取 Firebase Admin SDK JSON 文件
    // 使用 GoogleCredentials 初始化 FirebaseApp
}
// 通过 @ConditionalOnProperty(prefix="module-switch", name="firebase", havingValue="true") 条件加载
```

### 8.2 推送模式

`FireBaseServiceImpl` 支持两种推送模式：

| 模式 | 条件 | FCM API | 说明 |
|------|------|---------|------|
| **Token 精准推送** | tokens 非空 | `sendEachForMulticast` | 向指定设备列表推送 |
| **Topic 广播推送** | tokens 为空且 topic 非空 | `send` (Message) | 向订阅了该 Topic 的所有设备推送 |

### 8.3 Token 推送详细流程 (`sendNotification`)

```
1. 对 tokens 去重
2. 按 500 个一批分批推送 (BATCH_SIZE=500)
3. 每批:
   a. 构建 MulticastMessage (notification + tokens + data)
   b. 调用 FirebaseMessaging.getInstance().sendEachForMulticast(message)
   c. 若有失败 token, 重试一次
   d. 记录成功/失败 token 列表
4. 返回 FireBaseResultDTO (successList, failList, successCount, failCount)
```

### 8.4 推送数据载荷 (data map)

```java
// 所有类型都携带:
map.put("indexType", jumpInterface);  // 跳转页面类型

// appoint 和 drama 类型额外携带:
map.put("playId", playId);            // 短剧ID
map.put("seriesId", seriesId);        // 剧集ID
```

### 8.5 推送结果上报

推送完成后，通过 `ConfigEventReportAdapter.pushEventReportList()` 将推送成功的设备信息上报为事件（`PUSH_SHOW`），用于数据统计。

## 十、完整推送时序图

### 10.1 定时推送链路 (sign / drama)

```
XXL-Job "push"
    │
    ▼
TimerHandler.push()
    │
    ▼
TimerServiceImpl.push()
    │
    ├── 1. pushRepository.getUsableList()          // 查询所有启用的推送规则
    ├── 2. filterTriggerPushList()                  // 筛选 [now, now+5min) 内需触发的规则
    │       ├── sign   → isSignTimeInRange()        // 时分秒比较
    │       └── drama  → isTimeInRange()            // 完整时间比较
    │
    └── for each rule:
        │
        ├── 语言校验: 短剧语言 vs Topic语言
        │
        ├── [有绑定用户] ──► pushByTokens()
        │       │
        │       ├── pushUserRepository.list()       // 获取绑定用户
        │       ├── userRepository.getUserIdsByIdsAndLangId()  // 按语言筛选用户
        │       ├── userDeviceRepository.list()     // 获取设备Token
        │       └── fireBaseService.push(dto)       // 执行Firebase推送
        │               │
        │               └── sendNotification()
        │                       │
        │                       ├── [tokens非空] → 分批 sendEachForMulticast (500/批, 失败重试1次)
        │                       └── [tokens空+topic非空] → send (Topic广播)
        │
        └── [无绑定用户] ──► pushByTopic()
                │
                ├── dictionaryService.getDictById() // 获取Topic名称
                └── fireBaseService.push(dto)       // 执行Firebase Topic推送
```

### 10.2 客户端 Token 上报链路

```
APP客户端
    │
    │  POST /app/token  {deviceId, token, deviceSys, timeCity}
    ▼

    │
    ▼
```

## 十三、现有问题与注意事项

1. **权限注解全部注释**: `PushMsgController` 的所有 `@PreAuthorize` 均已注释，目前无权限控制
2. **triggerTime 校验不一致**: `addSysPush` 中未校验 `triggerTime` 为 null 的情况，但 `updateSysPush` 中有校验 (`if (ObjectUtils.isEmpty(triggerTime)) return failure`)
3. **appoint 类型不在定时推送范围**: `filterTriggerPushList` 只处理 sign 和 drama 类型，appoint（新剧预约）不参与定时扫描
4. **subscription 类型推送机制不明**: 订阅到期推送的触发机制未在定时任务中实现，`calculateTriggerTime` 返回 null，可能需要由支付回调事件驱动
5. **签到时间跨天问题**: `isSignTimeInRange` 不处理跨午夜场景，如果当前时间 23:58、advance 00:03，签到时间 00:01 会被漏触发
6. **SimpleDateFormat 线程安全**: 虽然每次 new 避免了线程安全问题，但建议统一使用 `DateTimeFormatter`
7. **签到类型触发时间**: 只计算了"下一次"触发时间，定时任务每次扫描 [now, now+5min) 窗口，签到类型需每天在该时间窗口内被扫到
8. **修改推送用户关联**: 采用"先删后增"策略，在事务内保证一致性
9. **Firebase 批量推送**: 每批最多 500 个 token，失败会重试 1 次
10. **语言校验**: 推送时会校验短剧语言与 Topic 语言一致性，以及用户语言与推送规则语言一致性
