## 一、表总览

推送模块共涉及 **13 张表**，按功能域分为 5 组：

| 分组 | 表名 | 说明 | 来源 |
|------|------|------|------|
| **推送核心** | `sys_push` | 推送配置主表 | 推送模块 |
| **推送核心** | `push_user` | 推送-用户手动绑定关联表 | 推送模块 |
| **推送核心** | `sys_push_crowd_pack_rel` | 推送-人群包关联表 | 推送模块 ✅新增 |
| **人群包** | `crowd_pack` | 人群包定义表 | 推送模块 ✅新增 |
| **站内信** | `station_letter` | 站内信记录表 | 站内信模块 ✅新增 |
| **邮件** | `email_send_log` | 邮件发送流水表 | 邮件模块 ✅新增 |
| **设备** | `user_device` | 用户设备表 (含FCM Token) | 用户模块 |
| **用户** | `sys_user` | 系统用户表 | 用户模块 |
| **用户** | `user_bind` | 用户三方绑定表 (含邮箱) | 用户模块 |
| **字典** | `sys_dict` | 系统字典表 (含订阅Topic/语言映射) | 系统模块 |
| **语言** | `sys_lang` | 语言表 | 内容模块 |
| **活动推送** | `activity_push_rule` | 活动推送规则主表 | 推送模块 |
| **活动推送** | `activity_push_rule_crowd` | 活动推送规则-人群包关联表 | 推送模块 |
| **活动推送** | `activity_push_history` | 活动推送触发记录表 | 推送模块 |
| **活动推送** | `activity_push_entry` | 活动推送入口配置表 | 推送模块 |

> ✅新增 = 测试改造版新增的表，生产环境不存在

## 二、ER 关系图
一个推送记录 可以推个多个用户， 一个用户 对应着多个推送记录，所以： 是多对多关系： 中间使用push_user表 关联。

一个推送记录 可以推个多个人群包， 一个人群包 对应着多个推送记录，所以： 是多对多关系： 中间使用sys_push_crowd_pack_rel表 关联。

一个用户可以绑定多个设备，所以： 一对多的关系

一个用户多个邮箱，所以： 一对多的关系

一个推送记录队以哦那个多个 站内信记录， 一个站内信记录 对应着多个推送记录

一个推送记录 对应多个邮件记录

## 四、表关系汇总

### 4.1 核心关系（外键逻辑）

| 主表 | 从表 | 关系 | 关联字段 | 说明 |
|------|------|------|----------|------|
| sys_push | push_user | 1:N | push_user.push_id = sys_push.id | 手动绑定用户 |
| sys_push | sys_push_crowd_pack_rel | 1:N | rel.push_id = sys_push.id | 关联人群包 |
| sys_push | station_letter | 1:N | station_letter.push_id = sys_push.id | 推送生成的站内信 |
| sys_push | email_send_log | 1:N | email_send_log.push_id = sys_push.id | 邮件发送流水 |
| crowd_pack | sys_push_crowd_pack_rel | 1:N | rel.crowd_pack_id = crowd_pack.id | 人群包被哪些推送引用 |
| crowd_pack | activity_push_rule_crowd | 1:N | rel.crowd_pack_id = crowd_pack.id | 人群包被哪些活动规则引用 |
| sys_user | push_user | 1:N | push_user.user_id = sys_user.id | 用户被哪些推送绑定 |
| sys_user | user_device | 1:N | user_device.user_id = sys_user.id | 用户的设备列表 |
| sys_user | user_bind | 1:N | user_bind.user_id = sys_user.id | 用户的绑定信息(含邮箱) |
| sys_user | station_letter | 1:N | station_letter.user_id = sys_user.id | 用户的站内信 |
| sys_user | email_send_log | 1:N | email_send_log.user_id = sys_user.id | 用户的邮件记录 |
| sys_user | activity_push_history | 1:N | history.user_id = sys_user.id | 用户的活动推送记录 |
| sys_dict | sys_push | 1:N | sys_push.subscription_topic_id = sys_dict.id | 订阅Topic |
| sys_lang | sys_push | 1:N | sys_push.lang_id = sys_lang.id | 推送语言 |
| activity_push_rule | activity_push_rule_crowd | 1:N | rel.rule_id = rule.id | 规则关联人群包 |
| activity_push_rule | activity_push_entry | 1:N | entry.rule_id = rule.id | 规则的入口配置 |
| activity_push_rule | activity_push_history | 1:N | history.rule_id = rule.id | 规则的触发记录 |

### 4.2 逻辑关系（非外键，业务查询时关联）

| 来源 | 目标 | 关联方式 | 说明 |
|------|------|----------|------|
| sys_dict (dict_topic=SUBSCRIPTION_TOPIC) | sys_lang | dict_value = sys_lang.id | 字典值存的是语言ID |
| user_bind | sys_user | user_bind.user_id = sys_user.id | 邮件推送时取 user_bind.user_email |
| crowd_pack.lang_ids | sys_lang | JSON数组包含 sys_lang.id | 人群包的语言筛选条件 |
| sys_push.play_id / series_id | play / series 表 | 外部服务查询 | 短剧/剧集名通过 playAdapter 获取 |

## 五、推送执行时的表访问路径

### 5.1 App内推送 (push Job, channel=0)

```
sys_push (states=true, channel=0, triggerTime在窗口内)
    │
    ├── [pushMode=0 指定人群]
    │       ├── sys_push_crowd_pack_rel → crowd_pack (人群包条件)
    │       │       └── 筛选 sys_user (按人群包条件 + last_login_time活跃)
    │       ├── push_user → sys_user (手动绑定的额外用户)
    │       │       └── 合并去重 → 最终目标用户列表
    │       ├── sys_user → user_device (获取FCM Token)
    │       └── sys_user → station_letter (生成站内信)
    │
    ├── [pushMode=1 不限人群]
    │       ├── sys_user (last_login_time > N月前, 分页)
    │       ├── sys_user → user_device (获取FCM Token)
    │       └── sys_user → station_letter (生成站内信)
    │
    └── [pushMode=2 Topic订阅]
            ├── sys_dict (dict_topic=SUBSCRIPTION_TOPIC, 获取Topic名)
            ├── sys_user (分页遍历, 生成站内信)
            └── station_letter (批量插入)
```

### 5.2 邮件推送 (emailPush Job, channel=1)

```
sys_push (states=true, channel=1, triggerTime在窗口内)
    │
    ├── [pushMode=0 指定人群]
    │       ├── sys_push_crowd_pack_rel → crowd_pack (人群包条件)
    │       ├── push_user → sys_user (手动绑定用户)
    │       ├── 合并去重 → 最终目标用户列表
    │       ├── sys_user → user_bind (获取user_email)
    │       └── email_send_log (记录发送结果)
    │
    └── [pushMode=1 不限人群]
            ├── sys_user (last_login_time > N月前, 分页)
            ├── sys_user → user_bind (获取user_email)
            └── email_send_log (记录发送结果)
```

### 5.3 客户端Token上报

```
APP客户端 → user_device (按deviceId查, 存在则更新token, 不存在则新增)
```

### 5.4 站内信查询 (APP端)

```
station_letter (按user_id分页查询, 按is_read=0统计未读数, 标记已读)
```

## 六、索引建议

基于推送执行路径，以下字段建议确保有索引：

| 表 | 字段 | 索引类型 | 原因 |
|----|------|----------|------|
| sys_push | states + channel + trigger_time | 联合索引 | 定时任务查询启用+渠道+时间窗口 |
| sys_push | trigger_type_code | 普通索引 | 按触发类型筛选 |
| push_user | push_id | 普通索引 | 查询推送绑定的用户 |
| push_user | user_id | 普通索引 | 查询用户被哪些推送绑定 |
| sys_push_crowd_pack_rel | push_id | 普通索引 | 查询推送关联的人群包 |
| sys_push_crowd_pack_rel | crowd_pack_id | 普通索引 | 查询人群包被哪些推送引用 |
| user_device | user_id | 普通索引 | 推送时查用户设备Token |
| user_device | device_id | 唯一索引 | Token上报时按设备查重 |
| station_letter | user_id + is_read | 联合索引 | APP端查询未读消息 |
| station_letter | message_id | 唯一索引 | 去重：同一规则同天同用户不重复 |
| station_letter | push_id | 普通索引 | 查询推送生成的站内信 |
| email_send_log | push_id | 普通索引 | 查询推送的邮件发送结果 |
| email_send_log | user_id | 普通索引 | 查询用户的邮件记录 |
| user_bind | user_id | 普通索引 | 邮件推送时查用户邮箱 |
| sys_user | last_login_time | 普通索引 | 活跃用户筛选 |
| activity_push_history | user_id + activity_push_rule_id | 联合索引 | 每日触发次数限制判断 |
| activity_push_rule_crowd | rule_id | 普通索引 | 查询规则关联的人群包 |
