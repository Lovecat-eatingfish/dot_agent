# 弹窗表结构关系详解

> 用途：理清 popup 相关表的关系，区分普通规则和AB实验规则

---

## 一、表结构总览

```
popup (弹窗主表) — 定义"弹什么"
    │
    │  1:N
    ▼
popup_rule (弹窗规则表) — 定义"什么时候弹、在哪弹、弹给谁"
    │
    ├── N:M → popup_rule_crowd (规则-人群包关联)
    ├── 1:N → popup_rule_country (规则-国家关联)
    ├── 1:N → popup_rule_lang (规则-语言关联)
    └── is_experiment 字段标记是否是AB实验规则

popup_target_rule (定向规则表) — 测试用的，面向指定用户或所有用户的测试规则
```

---

## 二、各表详细说明

### 1. popup（弹窗主表）

**作用**：定义弹窗的内容，即"弹什么"

| 字段 | 说明 | 示例 |
|------|------|------|
| id | 主键 | 1 |
| popup_name | 弹窗备注名称 | "新用户折扣弹窗" |
| popup_type | 弹窗类型 | 1=折扣, 2=推荐, 3=登录, 4=激励视频, 5=自定义, 6=通知, 7=评分, 8=推送通知 |
| device_sys | 操作系统 | -1=通用, 0=iOS, 1=Android |
| popup_status | 状态 | 0=关闭, 1=开启 |
| goods_type | 折扣类型 | 0=金币, 1=VIP订阅 |
| goods_id | 关联付费项ID | 100 |
| discount_style | 折扣样式 | 1-5 |
| popup_style | 弹窗样式 | 1=居中, 2=底部 |
| recommend_type | 推荐类型 | 1=系统推荐, 2=指定剧集 |
| popup_title | 弹窗标题 | "限时优惠" |
| popup_file_id | 弹窗图片文件ID | - |
| button_text | 按钮文案 | "立即购买" |
| allow_close | 允许关闭 | 0=否, 1=是 |

**一句话**：popup 表定义了弹窗长什么样、展示什么内容。

---

### 2. popup_rule（弹窗规则表）

**作用**：定义弹窗的触发条件，即"什么时候弹、在哪弹、弹给谁"

| 字段 | 说明 | 示例 |
|------|------|------|
| id | 主键 | 1 |
| popup_rule_name | 规则名称 | "首页推剧规则" |
| popup_id | 关联弹窗ID | 1 |
| position | 弹窗触发页面 | 1=首页, 2=播放页, 3=个人中心, 4=收藏页, 5=VIP页, 6=钱包页, 7=活动页 |
| trigger_timing | 触发时机 | 1=进入APP, 2=切换Tab, 3=进入播放页, 4=播放中, 5=打开付费面板, 6=关闭付费面板, 7=取消支付, 8=退出播放页, 9=页面加载完成, 10=返回按钮 |
| crowd_limit | 人群包限制 | 0=指定人群, 1=不限人群 |
| popup_count | 每日弹窗次数 | 0=不限, 3=每天最多3次 |
| watching_duration_type | 观看时长类型 | 0=不限, 1=大于等于, 2=小于等于, 3=区间 |
| duration_min | 时长最小值(秒) | 60 |
| duration_max | 时长最大值(秒) | 300 |
| status | 状态 | 0=关闭, 1=开启 |
| priority | 优先级 | 数字越小优先级越高 |
| **is_experiment** | **是否AB实验** | **false=普通规则, true=实验规则** |
| trigger_type | 触发类型 | 0=首次留存, 1=推剧, 2=退出充值礼物... |

**关键字段**：`is_experiment` 区分普通规则和AB实验规则

---

### 3. popup_rule_crowd（规则-人群包关联表）

**作用**：限制弹窗只对特定人群包的用户展示

| 字段 | 说明 |
|------|------|
| id | 主键 |
| popup_rule_id | 弹窗规则ID → popup_rule.id |
| crowd_id | 人群包ID → crowd_pack.id |

**关联关系**：一个规则可以关联多个人群包（N:M）

**示例**：
```
popup_rule_id=1 关联 crowd_id=10 (注册7天内未付费用户)
popup_rule_id=1 关联 crowd_id=20 (VIP用户)
```

**效果**：只有命中人群包10或人群包20的用户才能看到这个弹窗

---

### 4. popup_rule_country（规则-国家关联表）

**作用**：限制弹窗只在特定国家展示

| 字段 | 说明 |
|------|------|
| id | 主键 |
| popup_rule_id | 弹窗规则ID → popup_rule.id |
| country_code | 国家代码 |

**示例**：
```
popup_rule_id=1 关联 country_code="JP" (日本)
popup_rule_id=1 关联 country_code="US" (美国)
```

**效果**：只有日本和美国的用户才能看到这个弹窗

---

### 5. popup_rule_lang（规则-语言关联表）

**作用**：限制弹窗只对特定语言的用户展示

| 字段 | 说明 |
|------|------|
| id | 主键 |
| popup_rule_id | 弹窗规则ID → popup_rule.id |
| lang_id | 语言ID → sys_lang.id |

**示例**：
```
popup_rule_id=1 关联 lang_id=5 (日语)
popup_rule_id=1 关联 lang_id=2 (英语)
```

**效果**：只有日语和英语用户才能看到这个弹窗

---

### 6. popup_target_rule（定向规则表）

**作用**：测试用的规则，面向指定用户或所有用户的测试弹窗

| 字段 | 说明 |
|------|------|
| id | 主键 |
| popup_id | 弹窗ID → popup.id |
| target_type | 定向类型 | 0=ALL(所有用户), 1=USER(指定用户), 2=VERSION(指定版本) |
| target_value | 定向值(JSON) | 用户ID列表或版本号 |
| position | 弹窗触发页面 |
| trigger_timing | 触发时机 |
| popup_count | 可弹窗次数 |
| start_time | 开始时间 |
| end_time | 结束时间 |
| status | 状态 |
| priority | 优先级 |
| user_ids | 用户ID列表 |

**与 popup_rule 的区别**：
- `popup_rule` 是正式规则，通过人群包定向
- `popup_target_rule` 是测试规则，直接指定用户ID或面向所有用户

## 三、普通规则 vs AB实验规则

### 普通规则

```
popup (弹窗内容)
    │
    ▼
popup_rule (is_experiment=false)
    │
    ├── popup_rule_crowd (人群包定向)
    ├── popup_rule_country (国家定向)
    └── popup_rule_lang (语言定向)
```

**特点**：
- `is_experiment = false`
- 通过人群包、国家、语言进行定向
- 所有符合条件的用户都能看到

**示例**：
```sql
-- 日本的新用户，在播放页关闭付费面板时，弹出折扣弹窗
SELECT * FROM popup_rule 
WHERE popup_id = 1 
  AND position = 2 
  AND trigger_timing = 6 
  AND is_experiment = false
  AND status = 1
```

---

### AB实验规则

```
experiment_config (实验配置)
    │
    ├── 实验组 (60%流量) → popup_rule (is_experiment=true, popup_id=2)
    └── 对照组 (40%流量) → popup_rule (is_experiment=true, popup_id=3)
```

**特点**：
- `is_experiment = true`
- 通过实验系统分配流量（hash取模）
- 不同用户看到不同的弹窗

**示例**：
```sql
-- AB实验：60%用户看到新样式，40%看到旧样式
-- 实验组
INSERT INTO popup_rule (popup_id, position, trigger_timing, is_experiment, priority) 
VALUES (2, 1, 9, true, 1);

-- 对照组
INSERT INTO popup_rule (popup_id, position, trigger_timing, is_experiment, priority) 
VALUES (3, 1, 9, true, 2);
```

## 四、完整数据流

### 普通弹窗流程

```
APP请求 POST /app/popup {position: 2, triggerTiming: 6}
    │
    ▼
查询 popup_rule (position=2 AND triggerTiming=6 AND is_experiment=false)
    │
    ▼
过滤人群包 (popup_rule_crowd → crowd_pack)
    │
    ▼
过滤国家 (popup_rule_country)
    │
    ▼
过滤语言 (popup_rule_lang)
    │
    ▼
过滤频控 (popup_count)
    │
    ▼
轮询选择 (priority)
    │
    ▼
返回弹窗配置 (popup表)
```

### AB实验弹窗流程

```
APP请求 POST /app/popup {position: 1, triggerTiming: 9}
    │
    ▼
ExperimentContextFilter 加载用户实验信息
    │
    ▼
判断用户在哪个实验组 (hash取模)
    │
    ├── 实验组 → popup_rule_id=200 (is_experiment=true)
    └── 对照组 → popup_rule_id=201 (is_experiment=true)
    │
    ▼
返回对应的弹窗配置 (popup表)
```

## 五、关键区别总结

| 维度 | 普通规则 | AB实验规则 |
|------|---------|-----------|
| is_experiment | false | true |
| 定向方式 | 人群包 + 国家 + 语言 | 实验系统分配流量 |
| 流量分配 | 所有符合条件的用户 | hash取模分配百分比 |
| 配置位置 | popup_rule 表 | experiment_config + popup_rule 表 |
| 数据来源 | popup_rule + popup_rule_crowd + popup_rule_country + popup_rule_lang | experiment_config + experiment_group_config |
| 业务场景 | 运营配置的常规弹窗 | 需要A/B测试对比效果的弹窗 |

```java
// 1. 查询用户是否在AB实验中

if (CollUtil.isNotEmpty(userRelevantExperiment)) {
    // 用户在实验中，使用实验配置的弹窗规则

    // 直接查询这个规则，跳过正常的人群包过滤
} else {
    // 用户不在实验中，使用普通规则
    // 查询 is_experiment=false 的规则
    // 经过人群包、国家、语言、频控过滤
}
```

## 七、面试怎么说

**面试官："弹窗表是怎么设计的？"**

> 弹窗系统有 6 张核心表：
>
> 1. **popup**：弹窗主表，定义弹窗内容（类型、标题、图片、按钮）
> 2. **popup_rule**：弹窗规则表，定义触发条件（位置、时机、频次、优先级）
> 3. **popup_rule_crowd**：规则关联的人群包，实现精准定向
> 4. **popup_rule_country**：规则关联的国家，限制展示地区
> 5. **popup_rule_lang**：规则关联的语言，限制用户语言
> 6. **popup_target_rule**：测试规则，面向指定用户或所有用户
>
> 关键设计是 `popup_rule` 表的 `is_experiment` 字段：
> - `false` 表示普通规则，通过人群包定向
> - `true` 表示AB实验规则，通过实验系统分配流量
>
> 这样同一套表结构既能支持普通弹窗，也能支持AB实验弹窗。

**面试官追问："普通规则和AB实验规则有什么区别？"**

> **普通规则**：所有符合条件的用户都能看到，通过人群包、国家、语言进行定向。
>
> **AB实验规则**：通过hash取模分配流量，不同百分比的用户看到不同的弹窗。比如60%用户看到新样式（实验组），40%看到旧样式（对照组），然后对比转化率。
>
> 代码中通过 `is_experiment` 字段区分，实验规则走实验系统的逻辑，普通规则走人群包过滤的逻辑。
