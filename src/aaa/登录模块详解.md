# 登录模块详解

> 用大白话讲清楚这个项目的登录系统，包括群里说的那些概念

---

## 一、先搞清楚：有几种登录方式？

这个项目有 **3 种登录方式**，全部走 `AppUserController` → `AuthUserService`：

| 方式 | 接口 | 谁用 | 说明 |
|------|------|------|------|
| 游客登录 | `POST /app/user/login` | App 用户（首次打开） | 自动注册，不需要账号密码 |
| 三方登录 | `POST /app/user/third/login` | App 用户（升级账号） | Facebook / Google / Apple |
| 后台登录 | `POST /user/login` | 管理员 | 用户名 + 密码 |

---

## 二、游客登录（最重要，最常走的路）

### 大白话流程

用户下载 App → 打开 App → 什么都没填 → **自动就能用了**

这就是"游客登录"，用户不需要注册，系统根据 **设备 ID (deviceId)** 自动创建账号。

### 详细流程

```
用户打开 App
    │
    ▼
App 发送 POST /app/user/login  {deviceId: "abc123"}
    │
    ▼
AuthUserService.login()
    │
    ├── 1. 加分布式锁 (Redisson)，防止同一设备并发登录
    │
    ├── 2. 用 deviceId 去 sys_user 表查：这个设备有没有注册过？
    │
    │   ├── 【没注册过】→ 调用 registration() 自动注册：
    │   │   ├── 创建 SysUserDAO
    │   │   ├── userNickName = "Visitor_" + 随机8位字符
    │   │   ├── password = BCrypt.encode(deviceId)  ← 设备ID当密码用！
    │   │   ├── userType = 3 (游客)
    │   │   ├── userId = 12位编码字符串（从数据库ID生成）
    │   │   ├── 分配角色 ROLE_VISITOR
    │   │   └── ifFirstLogin = true
    │   │
    │   └── 【注册过】→ 直接用已有账号
    │       └── ifFirstLogin = false
    │
    ├── 3. 交给 Spring Security 认证：
    │   ├── 用户名 = userId（12位字符串）
    │   └── 密码 = deviceId（BCrypt加密后的）
    │
    ├── 4. 生成 JWT Token
    │
    ├── 5. 存到 Redis（key: user:{userId}）+ 存到数据库（authentication_token 表）
    │
    └── 6. 返回 LoginVO {token, userId, nickName, ifFirstLogin, ...}
```

### 群里说的"deviceId 当密码"是啥意思？

游客登录没有真正的"密码"，系统把 **设备 ID 当作密码** 来用：

```java
password = BCrypt.encode(deviceId)  // 把 deviceId 加密后存到 password 字段
```

这样做的好处是：同一个设备再次打开 App，用 deviceId 一查就能找到之前的账号，不需要用户记密码。

## 三、三方登录（升级游客账号）

### 大白话流程

用户已经游客登录了 → 在 App 里点了"用 Facebook 登录" → 系统把游客账号和 Facebook 账号绑定在一起

### 核心概念

**三方登录不是"替代"游客登录，而是在游客账号基础上"升级"**。

```
游客账号 (userType=3, ROLE_VISITOR)
    │
    │  用户点了 Facebook 登录
    │
    ▼
创建新账号 (userType=0, ROLE_MEMBER)  ← 新建一个"正式"账号
    │
    └── user_bind 表记录关联：
        ├── 新账号的 id = 正式用户
        └── bindUserId = 游客账号的 id  ← 绑定关系
```

### 详细流程

```
用户（已游客登录，有 JWT Token）点击"Facebook 登录"
    │
    ▼
App 调用 Facebook SDK，拿到 Facebook 的 accessToken 和用户信息
    │
    ▼
App 发送 POST /app/user/third/login
    {
        thirdType: "facebook",
        fUserId: "fb_123456",        ← Facebook 给的用户ID
        fToken: "xxx",               ← Facebook 的 accessToken
        idToken: "yyy",              ← Facebook 的 ID Token
        email: "user@example.com",
        imgUrl: "https://...",
        firstName: "张", lastName: "三"
    }
    │
    ▼
AuthUserService.newThirdLogin()
    │
    ├── 1. 加分布式锁
    │
    ├── 2. 去 user_bind 表查：这个 Facebook 账号有没有绑定过？
    │
    │   ├── 【没绑定过】→ 创建新的正式用户：
    │   │   ├── 创建 SysUserDAO (userType=0, ROLE_MEMBER)
    │   │   ├── password = BCrypt.encode(fUserId + "facebook")
    │   │   ├── 存储 Facebook 信息：fName, firstName, lastName, email, imgUrl
    │   │   ├── 创建 UserBindDAO 记录关联关系
    │   │   │   └── bindUserId = 游客账号的 id  ← 绑定！
    │   │   └── 生成新 JWT Token (channel: "third")
    │   │
    │   └── 【已绑定过】→ 切换到已绑定的正式用户
    │       └── 刷新 Token
    │
    └── 3. 返回新 Token → App 以后用这个 Token 访问
```

### Google 和 Apple 登录同理

| 平台 | user_bind 表字段 | userType |
|------|-----------------|----------|
| Facebook | fUserId, fName, firstName, lastName, email, imgUrl | 0 |
| Google | gUserId, gName, email, imgUrl | 2 |
| Apple | aUserId, aGivenName, aFamilyName, email | 1 |

### 群里说的"newThirdLogin vs thirdLogin"是啥？

两套代码，通过配置 `loginMethod` 切换：

| 方法 | 说明 |
|------|------|
| `thirdLogin()` | 旧版，简单的"有就绑定，没有就创建" |
| `newThirdLogin()` | 新版，处理更多边界情况（老账号重新绑定等） |

## 四、JWT Token 是什么？

### 大白话

JWT Token 就是一个"通行证"，用户登录后拿到这个通行证，以后每次请求都带着它，服务器一看就知道"这个人是谁"。

### Token 长什么样？

```
eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEyMzQ1LCJleHBpcmVUaW1lIjoxNzIwMDAwMDAwfQ.xxxxx
```

就是一串加密的字符串，里面包含：

| 字段 | 说明 |
|------|------|
| userId | 用户在数据库里的 ID |
| expireTime | 过期时间（时间戳） |
| channel | "third"（三方登录才有，游客登录没有） |

### 签名算法

```java
// HS256 对称加密，密钥是 "suguang"
JWTSigner hs256 = JWTSignerUtil.createSigner("HS256", "suguang".getBytes());
JWT.create().setExpiresAt(now).addPayloads(map).sign(hs256);
```

### Token 存在哪里？

| 位置 | 存什么 | 用途 |
|------|--------|------|
| Redis | `user:{userId}` → JWT 字符串 | 快速验证，单点登录控制 |
| 数据库 | `authentication_token` 表 | 持久化，Redis 没了还能查 |
| App | 请求头 `token` | 每次请求带着 |

## 五、请求是怎么验证身份的？（JwtAuthenticationFilter）

### 大白话

每个请求进来，都会经过一个"安检门"（JwtAuthenticationFilter），检查你带的"通行证"是不是有效的。

### 详细流程

```
App 发送请求（Header: token: "eyJxxx"）
    │
    ▼
JwtAuthenticationFilter.doFilterInternal()
    │
    ├── 1. 从请求头取出 token
    │
    ├── 2. 用 HS256 验证签名（密钥: "suguang"）
    │
    ├── 3. 解析 JWT，取出 userId, channel, expireTime
    │
    ├── 4. 检查过期时间：
    │      └── 过期了 → 删除 Token → 返回 403
    │
    ├── 5. 检查 channel：
    │      └── channel="third" → 验证 Token 是否是最新（防旧 Token 被盗用）
    │
    ├── 6. 加载用户权限：
    │      └── 从 Redis 查 userAuthorities:{userId}
    │          └── Redis 没有 → 从数据库查 → 写入 Redis
    │
    ├── 7. 设置 Spring Security 上下文
    │
    └── 8. 填充 UserContextHolder（ThreadLocal）
           ├── userId, token
           ├── deviceId, deviceSys, appVersion  ← 从请求头取
           ├── langId, language
           ├── cloudFrontCountryCode  ← AWS CDN 给的国家代码
           ├── deepLink, deepIp, deepUserAgent  ← 归因追踪用
           └── ...
```

### UserContextHolder 是啥？

就是一个 **ThreadLocal 变量**，存放当前请求的用户信息。在整个请求处理过程中，任何地方都可以通过 `UserContextHolder.get()` 拿到当前用户是谁。

```java
// 使用示例
Long userId = UserContextHolder.get().getUserId();
String deviceId = UserContextHolder.get().getDeviceId();
String langId = UserContextHolder.get().getLangId();
```

## 六、注册的时候还记录了哪些信息？

游客自动注册时，除了 userId 和密码，还记录了：

| 字段 | 来源 | 说明 |
|------|------|------|
| deviceSys | 请求头 `deviceSys` | 0=iOS, 1=Android |
| appVersion | 请求头 `appVersion` | App 版本号 |
| registerIp | 请求 IP | 注册时的 IP |
| lastLoginIp | 请求 IP | 最后登录 IP |
| countryCode | CloudFront 头 | 国家代码 |
| countryName | CloudFront 头 | 国家名称 |
| langId | UserContextHolder | 语言 ID |
| deviceId | 请求参数 | 设备 ID |

## 七、安全配置速查

```java
// SecurityConfig 中的关键配置：
.csrf().disable()                          // 关闭 CSRF
.sessionManagement().stateless()           // 无状态，不用 Session
.addFilterBefore(jwtFilter, ...)           // JWT 过滤器
.addFilterAfter(experimentFilter, ...)     // 实验上下文过滤器

// 公开接口（不需要登录）：
"/app/user/login"          // 游客登录
"/user/login"              // 后台登录
"/user/registration"       // 注册
"/af/**"                   // AppsFlyer 回调
"/fb/callback/**"          // Facebook 回调
"/swagger-ui/**"           // API 文档

// 其他所有接口：需要认证
.anyRequest().authenticated()
```

## 八、一句话总结

| 概念 | 一句话 |
|------|--------|
| 游客登录 | 用设备 ID 当密码，自动创建账号，用户无感知 |
| 三方登录 | 在游客基础上"升级"，绑定 Facebook/Google/Apple 账号 |
| JWT Token | 加密的"通行证"，包含 userId + 过期时间，每次请求带着 |
| UserContextHolder | ThreadLocal，存放当前请求用户的所有信息 |
| deviceId 当密码 | 游客没有真正密码，用设备 ID 加密后存 password 字段 |
| 分布式锁 | Redisson，防止同一设备/账号并发登录出问题 |
| channel: "third" | JWT 里的标记，表示这是三方登录的 Token，有额外验证 |
