# 消息推送模块 — 简历要点

> 用于写入简历的精炼版，每个要点控制在 1-2 行

---

## 一句话描述

> 负责全球化短剧 App 的多渠道消息推送系统，涵盖 FCM 推送、邮件推送、站内信、人群包定向等模块，服务覆盖 14 种语言的全球用户。

---

## 简历要点（选 3-4 条写入）

### 要点 1：多渠道推送架构

基于 Firebase Cloud Messaging 实现 App 推送，支持 Token 精准推送（单设备）和 Topic 广播（按语言群发）；通过 AWS SQS + SES 实现邮件推送异步链路，支持定时任务批量触发。

### 要点 2：人群包定向系统

设计并实现用户分群定向系统，支持 10+ 维度筛选（付费状态、注册时长、国家、语言、设备、观看时长等），被推送、弹窗、活动等多个业务模块复用，实现精细化运营触达。

### 要点 3：站内信系统

推送时自动生成站内信记录，实现消息中心（分页查询、未读数统计、单条/批量已读），通过全局唯一 message_id 保证同规则同天同用户不重复。

### 要点 4：语言隔离与全球推送

通过 FCM Topic + 字典表映射实现 14 种语言的消息隔离推送，结合 CloudFront 国家头部实现地理定向，确保不同语言用户收到对应语言内容。

### 要点 5：可靠性与频控

FCM 推送失败自动重试；邮件通过 SQS 队列削峰解耦；站内信通过 message_id 去重；定时任务 5 分钟窗口扫描避免重复触发；签到推送优化跨午夜窗口漏触发问题。

## 可追问的技术点（面试准备）

| 问题 | 简短回答 |
|------|---------|
| FCM Topic vs Token 精准推送怎么选？ | Topic 适合群发（按语言），Token 适合精准定向（按人群包） |
| 站内信怎么去重？ | message_id = push_{pushId}_{dateTag}_user_{userId}，插入前查重 |
| 邮件为什么用 SQS？ | 削峰（一次几千封）+ 可靠性（失败重试）+ 解耦 |
| 人群包怎么筛选？ | SQL 拼接条件查 sys_user，多人群包取 OR，单人群包内取 AND |
| 推送频控怎么做？ | 5 分钟扫描窗口 + 站内信 messageId 去重 + 日志追踪 |
